# 论文检阅（AI Academic Assistant）

论文检阅（AI Academic Assistant）是一个基于 Dify 平台构建的学术文献辅助工作流。项目以自然语言交互为入口，通过意图识别与路由机制，将用户请求分发到不同处理分支，用于支持论文检索、相似文献推荐、引文分析、全文阅读解析、参考文献分析以及 Zotero 文献保存等任务。

本项目的目标是为科研人员、研究生或需要进行文献调研的用户提供一个集成化的辅助工具，帮助用户在文献发现、初步筛选、内容理解和文献管理环节提高效率。项目输出结果依赖外部学术数据库、网页解析服务、大语言模型以及用户配置的 API，因此适合作为文献调研与阅读分析的辅助参考，不应替代人工审阅、正式学术判断或最终引用核验。

## 项目功能概述

工作流主要由 6 类功能分支组成：

1. **Search：文献检索**  
   根据用户输入的研究主题、关键词、作者、会议/期刊、年份或 CCF 等级等条件，构造检索请求，并从多个学术数据源获取候选论文信息。工作流中包含关键词提取、参数规范化、结果排序与基础筛选逻辑，用于辅助用户快速获得相关论文列表。

2. **Recommend：相似文献推荐**  
   当用户提供种子论文或明确的论文标识时，系统提取论文相关的核心概念或主题信息，并基于这些信息进行相似文献检索与推荐。该功能主要用于扩展阅读范围，帮助用户发现主题相近或研究思路相关的论文。

3. **Cite：被引分析**  
   基于目标论文的论文标识，查询其被引记录，并对引用该论文的文献进行基础统计与归纳分析。该分支可用于了解目标论文后续影响、相关研究方向变化以及部分引用关系。

4. **Read：论文全文解析**  
   根据论文链接、开放获取 PDF 或可访问的网页内容，调用网页/文档解析服务提取文本，再由大语言模型生成论文阅读报告。报告通常包括研究问题、方法思路、实验设置、主要结果、局限性与可能的后续方向。该功能的效果受论文全文可访问性、解析质量和模型能力影响。

5. **Analyze：参考文献分析**  
   面向目标论文的参考文献集合进行批量读取与归纳，尝试从相关工作、数据集、方法类型或研究脉络等角度生成总结。该功能适合用于辅助理解论文所处的研究背景，但仍需要用户结合原文进行核验。

6. **Save：Zotero 文献保存**  
   在用户配置 Zotero API Key 和 User ID 后，工作流可将选定论文的基础元数据整理为 Zotero 可接收的格式，并通过接口写入用户的 Zotero 文献库。该功能依赖前序检索结果中的论文标识和元数据完整性。

## 技术实现与依赖

本项目以 Dify DSL 工作流形式实现，主要涉及以下组件：

- **Dify 高级聊天工作流**：用于承载对话入口、意图路由、变量传递、节点编排和分支控制。
- **大语言模型**：用于用户意图识别、学术关键词提取、论文内容总结、引用分析和综合报告生成。当前工作流中使用 DeepSeek 系列模型作为主要模型配置。
- **学术数据源接口**：用于检索论文元数据、引用信息或相关文献。工作流中涉及的来源包括 Semantic Scholar、OpenAlex、arXiv、DBLP 等。
- **Jina Reader / 网页解析服务**：用于将论文网页或 PDF 相关页面转换为适合大语言模型处理的 Markdown 或文本内容。
- **Zotero API**：用于将论文条目保存到用户个人 Zotero 文献库。
- **JSONBin 或类似数据托管服务**：用于在需要时保存引文图谱或可视化所需的结构化数据。

## 部署前准备

导入并运行该工作流前，需要根据实际使用范围配置以下资源：

1. **Dify 平台环境**  
   需要具备可导入 DSL 文件并运行高级聊天工作流的 Dify 环境。

2. **模型服务配置**  
   需要在 Dify 中配置可用的大语言模型。若需要进行长文本论文解析，建议使用上下文窗口较大、推理能力较强的模型。

3. **Jina Reader API Key**  
   用于读取和清洗论文网页或开放访问 PDF 页面内容。

4. **Zotero API Key 与 User ID**  
   仅在需要启用文献保存功能时配置。

5. **JSONBin API Key**  
   仅在需要生成或托管引文图谱数据时配置。

6. **Semantic Scholar API Key（可选）**  
   无 API Key 时通常也可进行基础访问，但配置 Key 有助于提升调用稳定性和速率上限。

## 使用方式

### 1. 导入工作流

1. 在 Dify 工作台中新建应用。
2. 选择导入 DSL 文件。
3. 上传本项目提供的 `.yml` 工作流文件。
4. 检查模型、HTTP 请求节点和变量配置是否与当前环境一致。

### 2. 配置外部服务

根据工作流节点中的 HTTP 请求配置，替换相应的 API Key、User ID 或请求 Header。重点检查以下部分：

- 论文全文读取相关节点中的 Jina Reader 授权信息；
- Zotero 保存分支中的 Zotero API Key 与 User ID；
- 引文图谱托管相关节点中的 JSONBin API Key；
- 检索分支中可选的 Semantic Scholar API Key。

### 3. 示例指令

用户可以通过自然语言向智能体提出请求，例如：

```text
帮我检索近两年关于 Mamba 在序列建模中应用的论文。
```

```text
阅读这篇论文的全文，并总结它的研究问题、方法和实验结果：https://arxiv.org/abs/xxxx.xxxx
```

```text
分析这篇论文的被引情况，并总结后续研究主要关注哪些方向。
```

```text
把刚才检索结果中的第二篇论文保存到我的 Zotero 文献库。
```

## 适用场景

本项目适用于以下任务：

- 研究主题的初步文献检索；
- 根据已有论文扩展相关文献；
- 快速了解论文的研究问题、方法和实验设计；
- 对目标论文的引用情况进行初步梳理；
- 辅助整理论文元数据并保存到 Zotero；
- 为综述写作、选题调研或论文阅读提供前期材料。

## 使用限制与注意事项

- 检索结果受外部数据库覆盖范围、接口返回质量和关键词构造方式影响，不能保证完整覆盖某一研究方向的全部论文。
- 被引数据可能存在延迟、缺失或不同数据库之间统计口径不一致的问题。
- 全文解析依赖论文是否开放访问、网页是否可抓取以及解析服务的稳定性。
- 大语言模型生成的总结可能存在遗漏、概括不准确或误读原文的情况，关键结论应回到论文原文核对。
- Zotero 保存功能依赖论文元数据质量，保存后建议用户检查条目字段是否完整。
- 本项目主要定位为科研辅助工具，不提供学术结论的最终判定。
